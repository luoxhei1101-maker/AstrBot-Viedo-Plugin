# astrbot_plugin_rconsole

> 群里发一条分享链接，机器人自动把视频 / 图集 / 音乐扒出来发回来；
> 还支持点歌、扫码登录与三种状态查询图。
>
> 本插件是 Yunzai-Bot 插件 **R插件**（[rconsole-plugin](https://gitee.com/kyrzy0416/rconsole-plugin)，作者 zhiyu1998）在
> [AstrBot](https://github.com/AstrBotDevs/AstrBot) 上的移植版。业务逻辑与设计思路来自原项目，
> **遵循原项目的开源许可协议 —— 木兰宽松许可证第 2 版（Mulan PSL v2）**，`LICENSE` 与原项目一致。
>
> 原项目 README 的声明同样适用：素材来源于网络，仅供交流学习使用，**严禁用于任何商业用途和非法行为**。

**当前版本：v1.5.0** ｜ 适配 AstrBot `>=4.16, <5`（在 v4.28.1 上验证）

## 亮点速览

- **发链接即解析**，免 @ 机器人：抖音 / B站 / 快手 / 微博 / AcFun / 小红书 / 米游社 / 小黑盒 / 微视…
- **点歌**：`点歌 晴天` → 出一张列表图 → 回序号播放；网易云匿名即可用，QQ音乐配 Cookie 后 320kbps
- **扫码登录**：`#RNQ` 网易云、`#RBQ` B站，扫码后 Cookie 自动写进配置
- **三个状态图**：`#R菜单` 功能菜单、`#cookie状态` 一眼看清哪些 Cookie 失效、`#服务状态` 服务器负载
- **聊天里改配置**：`#R配置` 开关某个平台的解析、私信设置 Cookie、把解析内容切成「聊天记录」——不用开网页
- **部署形态不受限**：AstrBot 与协议端是否同容器都能发视频（详见[推荐部署环境](#推荐部署环境)）

## 必要环境

### AstrBot 本体

- AstrBot `>=4.16, <5`（本插件在 **v4.28.1** 上验证通过）
- Python 3.10+（AstrBot 自带，无需单独安装）

### 外部工具（按需）

| 工具 | 是否必需 | 用途 |
|---|---|---|
| `ffmpeg` + `ffprobe` | ✅ 必需（B站高清） | B站 DASH 音视频分离后合并 / 转码 / m3u8 拼接 |
| `node` | 推荐（抖音动图/评论） | 生成抖音 `a-bogus` 签名（复用原版 `a-bogus.cjs`）。官方 Docker 镜像已内置 |
| `yt-dlp` / `BBDown` / `aria2c` / `tdl` | 可选 | YouTube 下载 / B站高画质 / 多线程下载 / Telegram |

> 插件启动时会自动探测并打印结果，缺哪个日志里会直接列出来。除 ffmpeg 外都是「用不到就不装」。
>
> **关于 `node`**：抖音的**动图解析**与**评论**依赖 `a-bogus` 签名。没有 node 时会回落到 SSR
> 免登录通道 —— 视频和静态图仍可解析，但**动图会被发成静图**（SSR 页面把动图的视频轨抹掉了）。
> 想完整支持动图请确保有 node + 抖音 Cookie。

### Python 库

| 库 | 用途 | 官方镜像 |
|---|---|---|
| `aiohttp` | HTTP（AstrBot 自带） | ✅ |
| `qrcode[pil]` | 扫码登录生成二维码 | ✅ |
| `Pillow` | 点歌列表图 / 状态图渲染 | ✅（12.3.0） |
| `psutil` | `#服务状态` 采集 CPU / 内存 / 磁盘 | ✅（7.1.3） |
| 字体 `NotoSansCJK-*.ttc` | 图片里的中文 | ✅ |

> 本地部署缺 `qrcode` / `Pillow` / `psutil` 时，插件**不会崩**：二维码发不出去会提示、
> 图片自动退回文字输出。这些库只影响对应功能，不影响链接解析主流程。

## 安装

进入 AstrBot 插件目录 `data/plugins`（Docker 部署即挂载的 `AstrBot/data/plugins`）：

```bash
# 国内（Gitee）
git clone https://gitee.com/MuLinYa259/astrbot-viedo.git astrbot_plugin_rconsole
# 海外（GitHub）
git clone https://github.com/luoxhei1101-maker/AstrBot-Viedo-Plugin.git astrbot_plugin_rconsole
```

两个仓库内容一致，二选一。不想装 git 就从仓库页下载 zip 解压，**目录名保持
`astrbot_plugin_rconsole`**。

### 安装后

1. 到 AstrBot WebUI 的「插件」页点**重载**（或重启 AstrBot）。
2. 打开插件配置页，按需填 Cookie、勾选平台。
3. 看启动日志：会打印「识别规则 X 条 / resolver X 个」+ 外部工具探测结果。

## 推荐部署环境

| 项 | 推荐 | 说明 |
|---|---|---|
| 系统 | **Linux（Debian / Ubuntu）+ Docker** | 容器化隔离、一键升级、免手工配依赖 |
| 内存 | **≥ 2GB**（下载合并高清建议 4GB+） | AstrBot 本体 ~260MB + 插件 |
| 磁盘 | ≥ 5GB 空闲 | 媒体临时文件 + 本地缓存 |
| GPU | 不需要 | 纯网络 + ffmpeg |

> 走云服务器时记得在**安全组**放行 AstrBot 管理端口（默认 6185）与 OneBot 端口 ——
> 安全组拦截是「端口连不通」最常见的原因。

**支持的消息平台**：aiocqhttp（QQ OneBot）、Telegram、Discord、飞书 / Lark、企业微信、
QQ 官方、Slack、钉钉。

### 部署形态：AstrBot 与协议端是否同容器

**两种形态都支持。**

插件发出的媒体**自带数据**交给协议端，不需要协议端去读 AstrBot 容器里的临时文件：

| 形态 | 支持 |
|---|---|
| AstrBot 与协议端在**同一容器** | ✅ |
| **两个独立容器、无共享挂载**（本项目实际的部署形态） | ✅ |

代价是消息体比原始文件大约三分之一，属可接受范围。

## 使用

### 自动识别（免 @）

群里**直接发链接**即可，不需要 @ 机器人。

| 平台示例 | 链接 |
|---|---|
| 抖音 | `https://v.douyin.com/xxxx/` |
| B站 | `https://b23.tv/xxxx`、`https://www.bilibili.com/video/BVxxxx`、纯 `BVxxxx` |
| B站小程序卡片 | 从 B站 App 分享到 QQ 的小程序卡片 |
| 快手 / 微博 / 小红书 / AcFun / 贴吧… | 对应的分享链接 |

> 之所以能免 @，是因为 AstrBot 的正则过滤器**不受 `wake_prefix` 约束**，与原版 Yunzai 的 rule 行为一致。

**发送形式可切换**：默认「直发」（简介一条、媒体逐条）；管理员可以切成
「聊天记录」——整条解析打包成**一条合并转发**，不刷屏，也不再单独发「识别成功」提示：

```
#R配置 形式 聊天记录      切成合并转发
#R配置 形式 直发         切回默认
```

### 命令式指令

| 指令 | 作用 | 权限 |
|---|---|---|
| `翻en <内容>` / `翻ja` / `翻kr` … | 翻译成指定语言（日/英/韩/法/德/俄/西） | 所有人 |
| `#总结一下 <链接>` | 抓网页正文，交给 AstrBot 已配的 LLM 总结 | 所有人 |
| **`#R菜单`** / `#R帮助` / `#菜单` | **图片版功能菜单**（所有指令 + 使用教程） | 所有人 |
| **`#cookie状态`** / `#ck状态` | **图片**：所有 Cookie 是否失效 + 昵称 + 音乐会员等级 | 所有人 |
| **`#服务状态`** / `#bot状态` | **图片**：服务器负载 + Bot 账号 / 头像 | 所有人 |
| `点歌 <歌名>` | 点歌搜索（网易云 / QQ音乐） | 所有人 |
| `网易云点歌 <歌名>` / `QQ点歌 <歌名>` | 指定平台点歌 | 所有人 |
| **`#R配置`** / `#Rc` | **在聊天里改配置**：平台开关 / Cookie / 点歌 / 发送形式（见下节） | 🔒 管理员 |
| **`#RNQ`** / `#rnq` | **网易云扫码登录**（官方接口，扫码即写入 Cookie） | 🔒 管理员 |
| `#RBQ` / `#rbq` | B站扫码登录 | 🔒 管理员 |
| `#RBS` / `#rbs` | 查当前 B站 Cookie 是否有效、是哪个号 | 🔒 管理员 |

> 🔒 标记的指令**只有 AstrBot 管理员能用**（名单在全局配置 `admins_id`）。普通成员触发时
> 默认**静默忽略**（不回消息，避免暴露指令存在），只记一条告警日志。
>
> 原 Guoba 面板带来的 `#rns` / `#rks` / `#rkq` **已移除** —— 它们依赖的自建 API 服务
> 在本移植版里没有实现。`#rnq` 在 v1.3.0 一并移除过，**v1.5.0 用官方接口重新实现并恢复**。

### 三个图片命令

背景默认从随机图 API 随机取，主体是**毛玻璃面板**，深色半透明叠在模糊背景上保证文字清晰。

```
#R菜单       → 所有指令 + 使用教程（内容自动从规则表生成，不会和代码漂移）
#cookie状态  → 哪些 Cookie 失效了、是谁的号、音乐会员到什么时候
#服务状态    → CPU/内存/磁盘/负载/运行时长 + Bot 头像与账号
```

`#cookie状态` 只展示**平台 + 账号昵称 + 状态**，**不回显任何 Cookie 内容**；
音乐平台额外给会员状态与等级，未配置的平台合并成一行：

```
已配置
  网易云音乐  幕Ming    黑胶VIP Lv.7　到期 2027-10-31
  QQ音乐      NaiLuo   豪华绿钻　Lv5
  抖音                 已配置（该平台暂无可用的校验接口）
未配置
  哔哩哔哩 · 快手 · 微博 · 小红书 · 米游社 · 视频号 · 小黑盒
```

> QQ 昵称里的花体字母（`𝓝𝓪𝓲𝓛𝓾𝓸`）会自动折回普通字母显示，不会出现豆腐块。
> 三个命令都把外部请求**并行发出**，通常 1–3 秒出图；把「图片命令的随机背景 API」
> 留空则改用纯色底，会更快。

### 管理员配置（`#R配置`）

常用开关不必再开网页翻配置分组，在聊天里就能改。**只有 AstrBot 管理员可用**
（名单在全局配置 `admins_id`），统一入口 `#R配置`（也认 `#R设置` / `#Rc`，
**必须带 `#` 或 `/`** —— 裸的「R配置」会误伤正常聊天）。

```
#R配置                      当前配置总览（发送形式 / 平台数 / 点歌 / Cookie）
#R配置 帮助                  完整用法

#R配置 平台                  列出所有平台的开关状态
#R配置 平台 抖音 关           关掉抖音的自动解析（改成「开」即打开）
#R配置 形式 聊天记录          解析内容打包成一条聊天记录
#R配置 形式 直发             改回「简介 + 媒体」多条消息

#R配置 cookie               各平台 Cookie 配置情况
#R配置 cookie 小红书         私信里设置（两步式，见下）
#R配置 cookie 小红书 <整串>   直接设置
#R配置 cookie 小红书 清除     清空

#R配置 点歌 平台 网易云        默认点歌平台（也认 QQ音乐）
#R配置 点歌 数量 10           列表显示几首（1–50）
#R配置 点歌 发送 卡片          link / card / voice / file
#R配置 点歌 方式 列表          list=列表图+序号点播；直接=搜到就送
#R配置 点歌 开关 开            点歌总开关
```

平台名**中文名和内部 key 都认**（`抖音` / `douyin`、`小红书` / `xhs`），
改完立刻回一句「现在是什么」，不用再去配置页确认。

#### 发送形式：直发 vs 聊天记录

| 形式 | 表现 | 适合 |
|---|---|---|
| **直发**（默认） | 简介单独一条，图片 / 视频一条条发 | 想让内容直接可见 |
| **聊天记录** | 简介 + 全部媒体打包成**一条合并转发**，也不再发「识别成功」提示 | 内容多、不想刷屏 |

一条链接只对应一条消息，点开是完整聊天记录，里面每个媒体各占一条「消息」，
可以单独转发或保存。整条解析里**没有任何媒体**时不会硬凑聊天记录，
会退回普通文字情报（一条只有文字的转发点开跟普通消息一样，还多一次点击）。

#### Cookie：私信两步式 + 必备字段体检

Cookie 是凭据，**只能在私聊里设置**（群里执行只回一句提示，不写入）：

```
你（私聊）：#R配置 cookie 小红书
机器人：⌛ 请在 3 分钟内，把 小红书 的 Cookie 整串发给我……
你（私聊）：web_session=xxx; a1=yyy; …      ← 直接粘贴
机器人：✅ 小红书 的 Cookie 已保存：913 字符 / 12 个字段
```

- **允许不完整**：不必把 F12 里的字段一个不漏抄下来，平台也常加新字段
- **但必须有必备字段**：一个都没有说明粘错了平台，会拒收并点名缺什么

| 平台 | 必备字段（至少一个） | 平台 | 必备字段（至少一个） |
|---|---|---|---|
| 哔哩哔哩 | `SESSDATA` | 网易云音乐 | `MUSIC_U` |
| 抖音 | `sessionid` / `ttwid` | QQ音乐 | `qqmusic_key` / `qm_keyst` |
| 小红书 | `web_session` / `a1` | 米游社 | `cookie_token` / `ltoken` / `account_id` |
| 快手 | `did` / `didv` | 小黑盒 | `x_xhh_tokenid` |
| 微博 | `_T_WM` / `MLOGIN` | 视频号 | `hy_user` / `hy_token` |

确实要强行写入（比如平台改了字段名）就加「强制」：
`#R配置 cookie 小红书 强制 <整串>`。

> 保存时会**顺手清空同平台的「逐项填写」** —— 它的优先级更高，留着旧值会把刚
> 设置的整串顶掉。设置完发 `#cookie状态` 可校验有没有真的生效。

### 点歌

**首次使用需要打开开关**：插件配置 →「点歌」分组 → **开启点歌**（默认关闭）。

```
点歌 晴天            → 用配置里的「默认平台」
网易云点歌 晴天       → 强制走网易云
QQ点歌 晴天          → 强制走 QQ 音乐
```

平台写在「点歌」**前面或后面都认**，`#` / `/` 前缀可选（`#点歌 网易云 晴天` 也有效），
`QQ` 不分大小写。命令里写了平台就**只搜那个平台**，不会偷换；没写才用「默认平台」，
且该平台搜不到时会自动试另一个。

**搜索点歌与序号点播**（默认开启）：

```
点歌 晴天   → 返回一张列表图（默认 10 首）
1           → 60 秒内回复序号，播放第 1 首
```

- 列表图由插件现画（平台色条 + 封面 + 序号 + 歌名/歌手/专辑），**无二维码**
- 序号只在**该会话 60 秒内搜索过**时才生效，不会干扰群里的普通数字消息
- **序号是一次性的**：点播成功后列表立刻失效，再发同一个序号不会有任何反应；
  序号越界只给提示、不失效，可以直接改发别的序号
- 想恢复「搜到就直接发」的老行为：把「点歌」分组的**点歌方式**改成**直接送**（`direct`）

**发送方式可在配置里切换**（「点歌」分组 → 发送方式）：

| 方式 | 效果 | 什么时候用 |
|---|---|---|
| **文字 + 链接**（默认） | 列出「歌名 - 歌手 + 播放页链接」 | 想自己挑，最稳 |
| **音乐卡片** | 发音乐分享卡，群里直接点播放 | 想要「点开就播」 |
| **语音条** | 下载后发语音条 | ⚠️ 只适合短音频，见下 |
| **音频文件** | 以群文件形式发音频 | 想听整首 |

> 后三种方式在发送前会**校验直链是否真的能播**（有些歌没有会员只能拿到
> 试听或根本取不到）。校验不过就自动改发「歌名 + 链接」，不会塞给你一个
> 打不开的文件。

#### 音乐卡片需要配一次签名代理

音乐卡片的 `token` 由协议端**外部的签名服务**签发（协议端不自己生成卡片）。
插件内置了一个签名代理用来对接它，**部署时把协议端的 `musicSignUrl` 指过来即可**：

```jsonc
// 协议端 config/onebot_<uin>.json 或全局 config/snowluma.json
{ "musicSignUrl": "http://astrbot:18888/" }
```

改完**重启协议端容器**。代理端口可在「点歌」分组里改（改了两边要同步）。

- 代理会自动对齐卡片品牌：网易云的歌显示「网易云音乐」，QQ 音乐的显示「QQ音乐」
- 只有「发送方式 = 音乐卡片」依赖它，其他方式不受影响

#### 两个音乐平台的差别

| | 网易云 | QQ音乐 |
|---|---|---|
| 搜索 | ✅ 匿名可用 | ✅ 匿名可用 |
| 配了 Cookie 后 | 解锁 VIP 歌高音质 | 解锁完整版（否则只能试听） |
| Cookie 门槛 | 只要 `MUSIC_U=xxx`，**可扫码获取** | 一整串，**必须有 `qqmusic_key`** |
| 接口稳定性 | 很稳 | **有随机限流，偶尔要重试** |

> QQ 音乐接口偶有限流，插件已内置重试与 10 分钟搜索缓存；
> 连续失败时换 `网易云点歌 歌名` 更省事。

#### 关于「语音条」的限制（重要）

语音条会被转成**未压缩音频**再传输，体积很大，一首正常长度的歌协议端收不下。
所以语音条只适合**短音频**（插件内置 90 秒上限，超了会提示并改用链接）。

**想发整首请选「音频文件」或「音乐卡片」** —— 这两个不受此限制。

### 扫码登录

| 指令 | 平台 | 说明 |
|---|---|---|
| `#RNQ` | 网易云 | 走网易云网页端官方扫码接口，**不需要自建 API** |
| `#RBQ` | B站 | 容器内 `qrcode` + `PIL` 本地生成二维码 |

流程：管理员发指令 → 机器人回二维码 → 用对应**手机客户端**扫码 → 手机上点「确认登录」
→ Cookie **自动写进配置**，并回一条账号信息（昵称 / UID / 会员状态）确认。

二维码约 3 分钟过期，超时可在配置里调（`plugin` → 「B站扫码等待超时」，默认 180 秒）。

## Cookie 怎么填

**不用自己拼格式。** 原插件要求手拼 `odin_tt=xxx;sessionid=xxx;...`，漏个分号就失败。
现在每个平台两种填法，二选一：

| 填法 | 适合 | 怎么做 |
|---|---|---|
| ① 整段 Cookie | 已复制一整段 | 直接粘进对应字段，原样透传 |
| ② 逐项填写 | 只想填关键几个 | 点「添加条目」→ 下拉选字段名 → 填值（行内表格） |

逐项填写用 AstrBot 的 `template_list` 控件，渲染成**行内表格**。插件按
`key=value; key=value` 组装，并做**必需项体检**（缺关键项会在日志里点名）。

### 支持逐项填写的平台

| 平台 | 至少填一个 | 备注 |
|---|---|---|
| B站 | `SESSDATA` | 整段字段只存单值，自动补 `SESSDATA=` 前缀；**也可扫码** |
| 抖音 | `sessionid` 或 `ttwid` | 原版列出的 12 个 key 全部可填 |
| 快手 | `did` 或 `didv` | 本移植版新增（原版快手不走 Cookie） |
| 微博 | `_T_WM` 或 `MLOGIN` | |
| 小黑盒 | `x_xhh_tokenid` | 整段字段只存单值 |
| 网易云 | `MUSIC_U` | **推荐直接用 `#RNQ` 扫码** |
| QQ音乐 | 整串（含 `qqmusic_key`） | 从 `y.qq.com` 复制整段 Cookie，插件自动映射字段别名 |

> 取法：浏览器登录后 F12 → Network → 任意请求 → Request Headers → Cookie 整段复制。
>
> ⚠️ QQ 音乐 Cookie 里的 `qqmusic_key`（也叫 `qm_keyst`）**有效期约 12 小时**。
> 过期后取不到音频，重新抓一次即可 —— 用 `#cookie状态` 能立刻看出来。

### 配了 Cookie 之后的变化

**B站（提升最大）**：未配 Cookie 走 360P 老接口；配了走 **WBI 签名 + DASH 高清**
（默认 1080P），音视频分离后用 ffmpeg 无损合并（`-c copy`）。WBI 签名在
`core/bili_wbi.py` 完整实现，不依赖第三方库。

**抖音**：双通道自适应 —— 有 Cookie + node 时走**主接口**（`aweme/detail` + `a-bogus`），
否则回落 **SSR 免登录**。

> **为什么动图必须配 Cookie**：实测 SSR 分享页会把动图**降级成静态图** ——
> `aweme_type` 从 `68` 改写成 `2`，`images[].video` 整个抹掉只留 `url_list`。
> 所以在 SSR 路径下无论怎么改判断都识别不出动图。新版 `share/slides` 链接更是
> 客户端 SPA（HTML 里没有 `_ROUTER_DATA`），**只能**走主接口。

> **为什么图集图片先下载到本地**：抖音图片直链（`p3-pc-sign.douyinpic.com/...`）是
> **带签名的 CDN 地址**，需要正确 `Referer`，而且同一作品里 `.webp` / `.jpeg`
> 两个候选**哪个 403 是随机的** —— 没有固定顺序可用。AstrBot 发送端自己的下载器
> 既不补 Referer 也没有候选回退，一张失败就会让**整条消息链**失败。所以一律先用
> 插件自己的「补 Referer + 候选回退」下载器落到本地，发送端只发本地数据。

**快手**：双路 —— 优先网页 SSR 直解，失败回落第三方接口。

## 常见问题

**Q：发了链接没反应、也没日志？**
先查 AstrBot 全局配置 `cmd_config.json` 里的 `plugin_set` 是不是被改成了空数组 `[]`
（正常应是 `["*"]`）。这个配置会让所有插件的消息处理被跳过，症状就是「完全静默」。

**Q：某个平台的链接完全没反应？**
按顺序查三件事：① 插件的 `plugin.enabled_platforms` 有没有勾这个平台；
② 这个平台是不是在[支持列表](#支持的平台)里；③ 插件版本是不是旧的
—— 未命中规则 / 平台未启用 / 全局黑名单**三种跳过都会打日志**，直接看日志即可定位。

自 v1.6.0 起更省事：**启动日志会直接列出「已支持但没勾选」的平台**，
聊天里发 `#R配置 平台` 也能看到全部平台的开关状态，开一个：
`#R配置 平台 快手 开`。

**Q：第三方解析接口挂了？**
这类接口生命周期很短，默认的通用接口里只有部分还可用。全挂了就去
`plugin.parse_endpoints` 换新的，不用改代码。代码对 DNS 失败做了快速失败，
不会在死域名上白等重试。

**Q：重复发同一个链接会重新解析吗？**
不会。有**作品缓存**（2 小时），命中直接重发，跳过网络解析。

**Q：音乐卡片显示「发送者版本过低，无法展示内容」？**
说明协议端没能拿到有效的卡片签名。检查两件事：① 协议端 `musicSignUrl` 是否指向
本插件的代理（`http://astrbot:18888/`）；② 改完配置有没有**重启协议端容器**。
见[音乐卡片需要配一次签名代理](#音乐卡片需要配一次签名代理)。

**Q：`#cookie状态` 显示某个平台「已配置（暂无可用的校验接口）」？**
抖音 / 快手 / 小红书 / 视频号没有公开的账号校验接口，插件不会谎报「有效」，
只说明「已配置」。其余平台都是真实调用接口判断的。

**Q：点歌的语音条发不出来？**
正常现象，见[语音条的限制](#关于语音条的限制重要)。改用「音频文件」或「音乐卡片」。

## 与原版的差异

移植时把逻辑拆成了「平台解析（`platforms/`）」与「基础设施（`core/`）」两层，
解析器不依赖框架，可以脱离 AstrBot 单独测试 —— 这也是能在部署前验证逻辑的原因。

功能上的主要差异：

1. **LLM 复用 AstrBot 的模型**：不用再填 `aiBaseURL` / `aiApiKey` / `aiModel`。
2. **启动自检**：探测 ffmpeg / node / yt-dlp / BBDown / aria2c / tdl，日志直接列缺什么。
3. **作品缓存**：重复链接 2 小时缓存，命中直接重发，跳过网络解析。
4. **先发简介再发媒体**：标题 / 作者 / 类型先返回，大文件的合并 / 转码延后。
5. **不静默失败**：未移植的平台、被跳过的平台都会给明确提示或日志。
6. **新增原版没有的能力**：点歌（搜索 + 列表图 + 序号点播 + 音乐卡片）、
   网易云 / B站扫码登录、三个状态图、`#R配置` 聊天内改配置、解析内容合并转发。
7. **发送形式可选**：原版固定「简介 + 媒体」多条直发；本移植版可切成一条合并转发。

针对「等待」做了几处优化：HTTP 连接池复用、签名进程常驻、画质探测并发、
图片命令的外部请求全部并行（十几秒 → 1–3 秒）。

**`test_r_config.py` 里有一条特别值得留意的断言**：它用 AST 扫出所有
`self._save_conf("a.b", ...)` 的路径，逐个去 `_conf_schema.json` 里查是否存在 ——

下次启动就被删掉（v1.3.0 丢过一整套 Cookie）。以后新增可写配置项，这条断言会
直接把漏改 schema 的情况拦下来。

几个测试做了**环境自适应**：本机自动桩出最小 AstrBot API，容器里则用真实 AstrBot。
